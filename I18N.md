# Languages in Hidden Antwerp (i18n)

Hidden Antwerp is available in 8 languages: **English** (default and fallback), Nederlands, Français, Español, Italiano, Deutsch, Русский and Українська.

This document explains how that works and how to add or change texts.

## 1. The approach in one minute

- **No extra npm package.** The app uses a small translation layer in `src/i18n/`, built on the browser's and Node's own `Intl` APIs (`Intl.PluralRules`, `Intl.NumberFormat`, `Intl.DateTimeFormat`, `Intl.DisplayNames`, `Intl.ListFormat`). Packages like `next-intl` would also work, but they mainly add locale routing (`/fr/walks/...`), which this app doesn't need.
- **The URLs stay the same in every language** (`/walks/hidden-pubs` is `/walks/hidden-pubs` in every language). The language is remembered in a cookie.
- **The server renders each page in the visitor's language**, so there is never a flash of English first.
- **English is the master.** Every other language is compared with English. Anything that is missing is shown in English, so the app never shows `undefined`.

### How the language is chosen

In `src/i18n/server.ts` → `getLocale()`:

1. The visitor chose a language → cookie `ha-locale` (kept for 1 year).
2. First visit → the browser's language (`Accept-Language` header). `nl-BE` → `nl`, `fr-BE` → `fr`, `uk-UA` → `uk`, … Anything that isn't supported (e.g. `pt-BR`) → `en`.
3. Otherwise → English.

The choice is **also** saved in `localStorage` (`hidden-antwerp:locale`). If the cookie disappears (for example after clearing cookies), `LocaleSync` in `src/i18n/client.tsx` restores it from `localStorage`. The visitor's own choice always wins over browser detection.

> Next.js note: reading `cookies()` makes every page **dynamic** (rendered per request). That is intended: it lets every page arrive in the right language.

### Switching languages

The 🌐 language selector (`src/components/layout/LanguageSelector.tsx`) sits in the header on desktop and mobile. Choosing a language:

1. saves the cookie and `localStorage`;
2. sets `<html lang>`;
3. calls `router.refresh()`. Next.js re-renders the Server Components in the new language, and **Client Component state stays as it is**. The URL, a running game, the GPS navigation screen and the saved progress are not touched.

## 2. Where everything is

```
src/i18n/
  config.ts          the 8 languages, cookie name, native names + flags, browser-language matching
  translate.ts       createTranslator(locale): t(key, values), t.plural(key, count), English fallback
  messages.ts        loads the JSON files of every language
  server.ts          getLocale() / getTranslator() for Server Components and metadata
  client.tsx         <LocaleProvider>, <LocaleSync>, useT(), useLocale(), useChangeLocale()
  content.ts         walk content per language: LocalizedContent, pickContent (merge with English)
  content-shape.ts   compares a translated walk with the English one (used by the tests)
  locales/<lang>/    interface texts, split by topic:
    common.json      buttons, units ({value} m, {hours} h {minutes} min), city names
    navigation.json  header/footer/menu
    meta.json        page titles and descriptions (SEO, link previews)
    home.json        home page
    errors.json      404 and other error pages
    walks.json       walk cards, detail pages, practical information
    game.json        game screens (Hidden Pubs): team, votes, challenges, ledger, finale
    guide.json       guide screens (Poortjes, Classics): statuses, search tasks, collection
    gps.json         GPS and navigation: permissions, directions, distances

src/data/walks/<walk>/
  stops.ts / 01-….ts coordinates, addresses, images, answers, statuses: the SAME for every language
  content/en…        all texts of that walk in English (the master)
  content/<lang>…    the same texts in another language
```

The walks keep their **technical data only once** (ids, coordinates, addresses, image files, correct answers, route data). Only the texts exist per language:

| Walk | Technical data | Texts |
| --- | --- | --- |
| Poortjes van Antwerpen | `stops.ts`, `collection.ts`, `coordinates.json`, `routes.json` | `content/<lang>/` (index, deel-1…4, collection) |
| Classics of Antwerp | `stops.ts`, `images.json`, `coordinates.json`, `routes.json` | `content/<lang>.ts` |
| Hidden Pubs | `01-rococo.ts` … `08-boer-van-tienen.ts`, `finale.ts` | `content/<lang>.ts` |
| Upcoming walks | `upcoming-walks.ts` | in the same file, per language |

## 3. Using translations in code

### In a Server Component (pages, layouts, metadata)

```tsx
import { getTranslator } from "@/i18n/server";

export default async function Page() {
  const t = await getTranslator();
  return <h1>{t("home.titleStart")}</h1>;
}
```

### In a Client Component (`"use client"`)

```tsx
import { useT } from "@/i18n/client";

export function StopCounter({ current, total }: { current: number; total: number }) {
  const t = useT();
  return <p>{t("game.start.stopOf", { current, total })}</p>;
}
```

### Placeholders and plurals

Never glue sentences together (`"Stop " + current + " of " + total`): word order differs per language. Use placeholders:

```json
"stopOf": "Stop {current} of {total}"
```

Numbers in placeholders are formatted for the language automatically (`1,200` in English, `1.200` in German).

Plurals are an object with one text per plural category. English needs `one` and `other`; Russian and Ukrainian also need `few` and `many`:

```json
"stops": { "one": "{count} stop", "other": "{count} stops" }
"stops": { "one": "{count} остановка", "few": "{count} остановки", "many": "{count} остановок", "other": "{count} остановки" }
```

```ts
t.plural("walks.card.stops", 21); // "21 остановка"
```

### Dates, prices, distances, languages

Use the helpers in `src/features/walks/utils/format-walk.ts`, not hand-written formats:

- `formatDate("2026-09-28", locale)` → "September 28, 2026" / "28 september 2026" / "28 septembre 2026"
- `formatPrice(price, `${locale}-BE`)` → "€12.95" / "€ 12,95" / "12,95 €"
- `formatDistance(meters, t)`, `formatDuration(…, t)`, `formatLanguages(["en", "nl"], t)` → "English and Dutch" / "Engels en Nederlands"

TypeScript checks every key against the English JSON: a typo in `t("gps.turnLeftt")` is a compile error.

## 4. Adding a new interface text

1. Add the key to the right file in `src/i18n/locales/en/` with a **meaningful name**, e.g. `"gps.recenterMap": "Center map on me"`. (Never use the English sentence itself as the key.)
2. Add the same key to the other 7 languages.
3. Use it: `t("gps.recenterMap")`.
4. Run `npm run i18n:check`. It lists every missing, extra or empty text per language, and placeholders that got lost in a translation.

Forgot a language? The app shows English for that text and, in development, prints a warning in the console: `[i18n] Missing translation for "gps.recenterMap" in "fr"; showing English instead.`

## 5. Translating a location (a stop)

Example: a stop of the Classics walk.

1. Its coordinates, address and images are in `src/data/walks/classics-of-antwerp/stops.ts`. **Don't copy them**; they are shared by all languages.
2. Its English text is under its id in `content/en.ts` → `stops["classics-grote-markt"]`.
3. Add or change the same entry in `content/<lang>.ts`, with **exactly the same structure**: the same number of paragraphs, sections, "did you know" items, hints and list items, and the same section `kind`s.
4. Run `npx vitest run src/__tests__/i18n-walk-content.test.ts`. It fails if a translation is missing a text, has a different number of paragraphs, or changed a technical value (id, plate number, section kind, date checked, link).

### Rules for walk translations

- **Street names and addresses are never translated**: "Hoogstraat 21" is "Hoogstraat 21" in every language, and in Latin script in Russian and Ukrainian too, so visitors can match the street signs.
- **Antwerp names stay Antwerp names**: Grote Markt, Brabo, Onze-Lieve-Vrouwekathedraal, Rubenshuis, Vlaeykensgang, Schelde, Het Steen, Sint-Pauluskerk and house names like "De Gulden Handt". A short explanation in the visitor's language may follow in parentheses: "Grote Markt (main market square)". The established name of the city and the river may be used (Anvers, Amberes, Антверпен; l'Escaut).
- **Never change facts** while translating: no new dates, numbers, names or sources. History, legend and fiction stay separate (`kind`), and the research markers stay visible, translated: `[Historical research required]` → `[Recherche historique nécessaire]`.
- **Quotes** from sources (Smekens' book, the heritage inventory) are translated and stay in quotation marks. The captions of Smekens' 52 drawings are the exception: they are shown in the original Dutch of 1951, labelled as such.
- **Hidden Pubs' tavern ledger** is an in-world Dutch document: its original text is in the stop files, each language adds a `translation`, and Dutch visitors see only the original.
- **Hidden Pubs' text answers**: players type answers in their own language. The accepted answers of every language are in the stop files (`timeAnswers`, `horseAnswers`, `barrelGameAnswers`) and `finale.ts`. Case, accents, punctuation and spaces are ignored. When you translate a challenge, add the natural answers in your language there.
- **No alcohol pressure** in any language: the walk data tests check every language for shots and drinking challenges.

## 6. Translating a whole tour

1. Copy the English content (`content/en.ts`, or the `content/en/` folder for Poortjes) to `content/<lang>…` and rename the exports (`classicsContentEn` → `classicsContentPt`).
2. Translate every text; leave ids, keys, `kind`s, dates, links and placeholders like `{address}` exactly as they are.
3. Register the language in that walk's `content/index.ts`:
   ```ts
   export const classicsContent: LocalizedContent<ClassicsContent> = {
     en: classicsContentEn,
     // …
     pt: classicsContentPt,
   };
   ```
4. The walk card and detail page now list the language automatically (`walk.languages` comes from the content that exists).
5. Run the tests (see section 8).

A translation may be partial while you work on it: whatever is missing is taken from English. Lists (e.g. the paragraphs of one story) are replaced as a whole, so a story never mixes two languages.

## 7. Adding a 9th language (e.g. Portuguese)

1. `src/i18n/config.ts`: add `"pt"` to `locales` and `pt: { nativeName: "Português", flag: "🇵🇹" }` to `localeNames`.
2. Copy `src/i18n/locales/en/` (the JSON files and the `index.ts` that bundles them) to `src/i18n/locales/pt/` and translate the JSON files (use the plural categories Portuguese needs: `one` and `other`).
3. In `src/i18n/messages.ts`: `import pt from "./locales/pt";` and add `pt` to `messagesByLocale`.
4. Run `npm run i18n:check` until Portuguese is complete.
5. Translate the walks (section 6). Until then they appear in English.
6. Check `common.cities.antwerp` ("Antuérpia") and the fonts: Portuguese uses `latin` + `latin-ext`, which the layout already loads (Cyrillic is also loaded for Russian and Ukrainian).

The language selector, browser detection (`pt-BR` → `pt`), date/number formatting and page metadata then work automatically.

## 8. Checking translations

```bash
npm run i18n:check                                        # interface texts: missing / extra / empty / lost placeholders
npx vitest run src/__tests__/i18n-walk-content.test.ts    # every walk translation has the English structure
npx vitest run src/__tests__/i18n.test.ts                 # translator, plurals, fallback, detection, dates
npx vitest run src/__tests__/walk-data.test.ts            # walk rules (alcohol, answers, markers) in EVERY language
```

In the browser: choose a language with 🌐, refresh (the language stays), open a walk, start it, and check the GPS screen. Check German for long words on small screens, and Russian and Ukrainian for Cyrillic.

## 9. What is deliberately not translated

- **Brand and proper names**: "Hidden Antwerp", "Hidden Pubs", café names, beer brands.
- **Street names and addresses**, and Antwerp place and house names (see section 5).
- **The captions of Smekens' drawings** (a quoted Dutch source from 1951) and the titles of Dutch sources in the source lists (bibliographic titles).
- **Hidden Pubs' ledger**: Dutch original + translation.
- **Playtest and developer tools** (the yellow "Playtest tools" / "Simulated GPS" panels): they are for the team, not for visitors, and stay in English.
